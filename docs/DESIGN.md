# Дизайн-документ физического движка «physengine»

Версия: 1.0 · Дата: 27.11.2026 · Статус: проект (блок A в разработке)

## 1. Введение

### 1.1. Назначение проекта

physengine — учебный физический движок на C++20, разрабатываемый как курсовой
проект на факультете физики и ИТ. Движок предназначен для численного
моделирования физических явлений: от классической механики точки до
молекулярно-кинетической теории (МКТ) и элементов ядерной физики. Каждая
модель проверяется против аналитических решений, что делает проект не только
программной, но и физической работой.

### 1.2. Цели и задачи

Цель — движок, на котором можно воспроизводить школьную и вузовскую
механику, сравнивать численные методы и наглядно демонстрировать явления.

Задачи:

1. Ядро без зависимостей от графики и ввода (библиотека `libphys`).
2. Сменные численные интеграторы: явный Эйлер, симплектический Эйлер,
   velocity Verlet, Рунге–Кутта 4.
3. Библиотека сил: гравитация, пружина, сопротивление среды; далее —
   центральные поля, потенциал Леннарда–Джонса, кулоновское взаимодействие.
4. Система сцен: текстовые пресеты физических экспериментов.
5. Два бэкенда рендера за одним интерфейсом: headless (PNG → MP4) и
   оконный (SFML, локальная сборка).
6. Экспорт временных рядов (CSV) для графиков в matplotlib.
7. Юнит-тесты на аналитических решениях (doctest).

### 1.3. Границы проекта

В текущей версии (курсовая работа) реализуются плоские (2D) модели.
Трёхмерность, деформируемые тела и сеточные методы (CFD) не входят в охват;
возможность их добавления закладывается архитектурно.

## 2. Архитектура

### 2.1. Обзор

Движок разделён на слои с однонаправленными зависимостями: ядро не знает
ни о рендере, ни о сценах; сцены не знают о рендере; рендер только читает
состояние мира. Это позволяет запускать один и тот же код и в песочнице
без дисплея (headless), и на домашней машине в интерактивном окне.

```
┌────────────────────────────────────────────────────────────┐
│                     Слой приложений                        │
│   CLI (parse scene)      Оконное приложение (SFML+ImGui)   │
└──────────────┬───────────────────────────┬─────────────────┘
               │                           │
┌──────────────▼─────────────┐   ┌─────────▼─────────────────┐
│      Ядро libphys          │   │   Рендер-бэкенды          │
│  World  Body  ForceFn      │   │  IRenderer (интерфейс)    │
│  Integrator (стратегия)    │   │   ├ SoftwareRender→PNG    │
│  forces:: gravity/spring/… │   │   └ SfmlRender (опция)    │
└──────────────┬─────────────┘   └─────────▲─────────────────┘
               │                           │
┌──────────────▼───────────────────────────┴─────────────────┐
│               Слой данных: сцены (.scene), CSV, кадры       │
└────────────────────────────────────────────────────────────┘
```

### 2.2. Главный цикл

Ключевое architectural-решение — фиксированный шаг физики при переменном
шаге рендера (fixed timestep). Физика шагает с постоянным `dt` (например,
1/240 с), рендер — по мере готовности кадров; аккумулятор времени
догоняет реальное время. Это делает симуляцию воспроизводимой: одинаковый
ввод всегда даёт одинаковую траекторию независимо от FPS.

```
пока окно открыто / не конец сцены:
    accumulator += frameTime          # реальное время кадра
    пока accumulator >= dt:
        scene.forces(world.bodies)    # набрать силы
        world.step(dt)                # интегратор продвигает систему
        accumulator -= dt
    renderer.draw(world.bodies)       # отрисовать текущее состояние
    recorder.maybeSample(t, bodies)   # CSV-семплирование по расписанию
```

### 2.3. Модули ядра

| Модуль | Заголовок | Ответственность |
|---|---|---|
| Математика | `math_vec2.hpp` | Vec2, скалярное/векторное произведение, нормировка |
| Сущности | `body.hpp` | Точечное тело: масса, позиция, скорость, аккумулятор силы |
| Силы | `forces.hpp` | Гравитация, пружина, линейное/квадратичное сопротивление |
| Интеграторы | `integrator.hpp` + реализации | Интерфейс «стратегия»; Эйлеры, Верле; RK4 — в блоке A |
| Мир | `world.hpp` | Контейнер тел, смена интегратора, единый `step(dt)` |

Продолжение: парсер сцен (`scene.cpp`), коллизии (`collision/`), пространственная сетка (`spatial_hash.hpp`), запись CSV (`recorder.hpp`), софтверный рендер (`render/software.cpp`).

### 2.4. Паттерны проектирования

- **Стратегия** — сменные интеграторы за одним интерфейсом; сцена выбирает метод по имени.
- **Функциональная композиция сил** — каждая сила является свободной функцией, изменяющей аккумуляторы; сцена комбинирует их в один `ForceFn`.
- **Наблюдатель** — рендер и CSV-рекордер читают состояние после шага, не вмешиваясь в физику.

### 2.5. Формат сцены

Сцена — текстовый файл с секциями `meta` (dt, длительность, интегратор),
`bodies` (позиция, скорость, масса, радиус) и `forces` (имя + параметры).
Пример — `examples/oscillator.scene` (см. репозиторий). Парсер — линейный,
без внешних зависимостей; грамматика стабилизируется в блоке A.

### 2.6. Визуализация (обязательный слой)

Принцип проекта: **каждое моделирование должно быть просматриваемым, а не
только считаемым**. Поэтому визуализация — не надстройка, а обязательный
слой конвейера, доступный каждой сцене:

1. **Программный рендер** (`render.hpp`): холст RGB, фоновая сетка,
   светящиеся тела с ореолом, следы траекторий с затуханием, камера
   «мир → пиксели» (мировая ось Y вверх, пиксельная — вниз). Кодирование
   PNG — `stb_image_write` (header-only, без зависимостей).
2. **Кадры → видео**: демо пишет PNG-кадры с частотой 60 к/с, Make-цель
   `demo_video` собирает MP4 (h264, yuv420p) через ffmpeg. Видео
   открывается в любом плеере и прикладывается к защите курсовой.
3. **CSV → графики**: рекордер (`recorder.hpp`) пишет временные ряды
   (t, x, y, vx, vy, E для каждого тела); по ним строятся графики
   траекторий и энергий (matplotlib) для текста курсовой.
4. **Оконный бэкенд (опция)**: тот же интерфейс рендера за SFML-окном с
   ползунками параметров — для интерактивных экспериментов дома.

Эталонный пример — демо «двойная звезда» (`make demo_video`): 30 секунд
полного орбитального периода, следы обеих звёзд, контроль сохранения
энергии (максимальный дрейф ~10⁻¹⁴) и график T/U/E (рис. в разделе 7).

## 3. Физические модели

### 3.1. Каталог явлений механики

Каждое явление = сцена-пресет + обязательная численная проверка.

**Блок A. Материальная точка**

| # | Явление | Модель | Проверка |
|---|---|---|---|
| A1 | Свободное падение | F = mg | y(t) = y₀ − gt²/2; время падения |
| A2 | Баллистика без сопротивления | F = mg | Дальность L = v²sin2α/g |
| A3 | Баллистика с сопротивлением | F = mg − k₁v − k₂v\|v\| | Предельная скорость v∞ = √(mg/k₂) |
| A4 | Центральное поле (спутник) | F = −GMm r̂/r² | Законы Кеплера: эллипс, T² ∝ a³, постоянство секториальной скорости |

**Блок B. Осцилляции**

| # | Явление | Модель | Проверка |
|---|---|---|---|
| B1 | Пружинный осциллятор | F = −kx | T = 2π√(m/k); сохранение E |
| B2 | Затухающие колебания | F = −kx − cv | Логарифмический декремент λ = cT/2m; добротность Q |
| B3 | Вынужденные колебания | F = −kx − cv + F₀cos ωt | АЧХ: резонанс при ω = √(ω₀² − 2β²) |
| B4 | Нелинейный маятник | F = −mg sin θ (θ до π) | T(θ₀) = T₀(1 + θ₀²/16 + …) |
| B5 | Связанные осцилляторы | Две массы, три пружины | Нормальные моды: ω± = √(k/m), √((k+2κ)/m); биения |

**Блок C. Столкновения и рассеяние**

| # | Явление | Модель | Проверка |
|---|---|---|---|
| C1 | Упругие столкновения шаров (1D/2D) | Импульсный метод, e = 1 | Сохранение p и E; формулы скоростей |
| C2 | Неупругие столкновения | 0 < e < 1 | Доля потерь энергии 1 − e² |
| C3 | Рассеяние Резерфорда | F = κ/r² (отталкивание) | b = (κ/2E)·ctg(θ/2) по ансамблю траекторий |

**Блок D. N-body**

| # | Явление | Модель | Проверка |
|---|---|---|---|
| D1 | Двойная звезда, планетная система | Σ парных гравитаций | Теорема вириала 2⟨T⟩ = −⟨U⟩ |

**Блок E. Мост к МКТ**

| # | Явление | Модель | Проверка |
|---|---|---|---|
| E1 | Цепочка масс-пружин | N масс, пружины соседства | Дисперсия ω(k) = 2√(k/m)·sin(ka/2) |
| E2 | Газ Леннарда–Джонса | U(r) = 4ε[(σ/r)¹² − (σ/r)⁶] | Распределение Максвелла; вириальное уравнение; фазовый переход |

Планируемые расширения после МКТ — радиоактивные цепочки распадов
(стохастическое моделирование, dN/dt = −λN) и кулоновское рассеяние
заряженных частиц как мостик к ядерной физике.

### 3.2. Численные методы

Все интеграторы решают систему ọ = f(t, y) для каждой материальной точки.

| Метод | Формула | Порядок | Свойства |
|---|---|---|---|
| Явный Эйлер | xₙ₊₁ = xₙ + vₙΔt; vₙ₊₁ = vₙ + aₙΔt | O(Δt) | Энергия дрейфует вверх; учебный «антипример» |
| Симплектический Эйлер | vₙ₊₁ = vₙ + aₙΔt; xₙ₊₁ = xₙ + vₙ₊₁Δt | O(Δt) | Энергия ограничена; простота |
| Velocity Verlet | xₙ₊₁ = xₙ + vₙΔt + aₙΔt²/2; vₙ₊₁ = vₙ + (aₙ+aₙ₊₁)Δt/2 | O(Δt²) | Симплектический, обратим; стандарт МД |
| РК4 | классические четыре стадии | O(Δt⁴) | Точен на коротких временах; не сохраняет энергию глобально |

Критерий сравнения в экспериментальной главе курсовой:

1. Дрейф полной энергии осциллятора на 10 периодов, |E(t) − E₀|/E₀.
2. Эмпирический порядок сходимости: наклон log ε(log Δt), где ε — ошибка
   против аналитики в момент t.
3. Максимальный устойчивый Δt (для явного Эйлера на осцилляторе —
   известный порог T/π).
4. Время счёта на N тел.

### 3.3. Столкновения

Мгновенная импульсная модель: при перекрытии тел вычисляется нормаль
контакта n̂, относительная скорость вдоль нормали v_rel·n̂ < 0 и импульс
j = −(1+e)·(v_rel·n̂)/(1/m₁ + 1/m₂). Скорости обновляются векторно,
позиционная коррекция (проекция) устраняет проваливание. Парные проверки
предваряются broad-phase на пространственной хеш-сетке (ячейка ≈ 2r_max),
что снижает сложность с O(N²) до ~O(N).

## 4. Технологии

| Слой | Выбор | Обоснование |
|---|---|---|
| Язык | C++20 (g++ ≥ 13) | Широкая поддержка структур,ranges, constexpr-математика |
| Сборка | Make | Прозрачность для учебного проекта; CMake — опция |
| Тесты | doctest (header-only) | Быстрая компиляция, читаемые сообщения |
| Рендер headless | собственный софтверный растеризатор → PNG | Ноль зависимостей, работает в CI без дисплея |
| Видео | ffmpeg (кадры → MP4) | Стандартный инструмент |
| Графики | CSV → matplotlib | Качественная публикационная графика |
| Рендер оконный | SFML 2.6 + Dear ImGui (локально, опция) | Интерактивные ползунки параметров в реальном времени |

Готовые физические движки (Box2D, Bullet, PhysX) сознательно не
используются: цель курсовой — написать физику самостоятельно.

## 6. Риски и их снижение

| Риск | Вероятность | Смягчение |
|---|---|---|
| Расползание scope (МКТ, ядерка раньше времени) | Высокая | Жёсткая последовательность блоков; МКТ только после E1 |
| Неустойчивость явного Эйлера на связанных системах | Средняя | Верле по умолчанию; Эйлер — как сравнение |
| Производительность O(N²) в газе ЛЖ | Средняя | Пространственная сетка; N ≤ 2000 на CPU |
| Расхождение с аналитикой из-за ошибок в единицах | Средняя | Все параметры в СИ; тесты фиксируют константы |

## 7. Результаты эталонного демо (двойная звезда)

Первый визуализируемый прогон движка — D1 «двойная звезда»: m₁ = 2, m₂ = 1,
расстояние 4, круговые орбиты вокруг центра масс, Verlet с dt = 1/480 с.

| Артефакт | Где | Содержание |
|---|---|---|
| Видео MP4 | `output/binary_stars.mp4` | 30 с (полный период T = 29.0 с), 60 к/с, 1280×720 |
| Кадры PNG | `output/frame_*.png` | 1801 кадр со следами орбит и ореолами звёзд |
| Временные ряды | `output/binary_stars.csv` | t, x, y, vx, vy, E для обеих звёзд |
| Графики | `docs/img/binary_stars.png` | Траектории + ход T, U, E |

Численный контроль: максимальный относительный дрейф полной энергии
за 30 с — 4·10⁻¹⁴ (Verlet); аналитическая проверка периода — тест
`Двойная звезда: кинематика круговых орбит` (возврат в исходные точки
после T с погрешностью O(dt²)).
